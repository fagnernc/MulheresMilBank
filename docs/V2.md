# Mulheres Mil Bank V2

## Objetivo

A V2 prepara o simulador para oficinas com múltiplas turmas temporárias. Cada turma representa uma atividade independente, com período de validade, senha própria e contas fictícias geradas para as participantes. A V1 permanece preservada nesta etapa: não há importação automática nem alteração de `alunas.csv` ou `estado.json`.

## Modelo de dados

O banco SQLite fica em `DATA_DIR/mulheresmilbank.db`. A camada usa somente `sqlite3` da biblioteca padrão do Python.

| Tabela | Responsabilidade |
| --- | --- |
| `turmas` | Dados da atividade, período de uso, saldo inicial em centavos, senha protegida e eventual encerramento. |
| `alunas` | Contas temporárias: nome, turma, código global único de seis dígitos e saldo em centavos. |
| `transacoes` | Registro de cada Pix simulado, com turma, origem, destino, valor em centavos e horário. |

As chaves estrangeiras, `CHECK constraints` e índices de turma/origem/destino protegem a integridade e as consultas essenciais. O código de conta é globalmente único, numérico, tem seis dígitos e não começa com zero.

## Estados da turma

O estado não é armazenado para evitar duplicação. Ele é derivado explicitamente dos horários e de `encerrada_em`:

| Estado | Regra |
| --- | --- |
| `AGENDADA` | Antes de `inicio_em`. |
| `ATIVA` | De `inicio_em` até `validade_em`, sem encerramento. |
| `EXPIRADA` | Após `validade_em`. |
| `ENCERRADA` | `encerrada_em` preenchido. |

Os instantes são gravados com offset ISO 8601. O fuso padrão é `America/Maceio`, configurável por `APP_TIMEZONE`, evitando que o fuso UTC do contêiner altere acidentalmente a validade das atividades.

## Gestão administrativa de turmas

A Etapa 2 integra a gestão de turmas ao painel administrativo protegido pela sessão existente do professor. As rotas abaixo não aceitam acesso sem essa sessão:

| Rota | Finalidade |
| --- | --- |
| `GET /admin/turmas` | Lista as turmas com status, quantidade de alunas e datas. |
| `GET /admin/turmas/nova` | Exibe o formulário de criação. |
| `POST /admin/turmas/criar` | Cria uma turma com saldo em centavos e senha protegida. |
| `GET /admin/turmas/<id>` | Mostra detalhes e ações de gerenciamento. |
| `POST /admin/turmas/<id>/encerrar` | Encerra a turma. |
| `POST /admin/turmas/<id>/validade` | Altera a validade sem alterar `encerrada_em`. |

A listagem usa uma consulta com `LEFT JOIN` e `COUNT`, evitando uma consulta adicional por turma. Turmas ativas e agendadas aparecem primeiro; dentro de cada grupo, a ordem é da criação mais recente para a mais antiga. A alteração de validade não reabre uma turma encerrada porque o status continua derivado de `encerrada_em`.

O formulário recebe valores monetários como texto e os converte com `Decimal` para centavos. A senha da turma é usada somente na criação e nunca é devolvida pelo SQLite ou exibida pela interface.

## Cadastro de alunas

A Etapa 3 adiciona cadastros individuais e em lote ao gerenciamento de cada turma. O cadastro em lote é feito digitando ou colando **um nome por linha**; não há importação CSV nesta etapa e nenhum identificador institucional é solicitado.

| Rota | Finalidade |
| --- | --- |
| `GET /admin/turmas/<id>/alunas/nova` | Exibe o formulário de cadastro individual. |
| `POST /admin/turmas/<id>/alunas/criar` | Cria uma conta com código aleatório de seis dígitos. |
| `GET /admin/turmas/<id>/alunas/lote` | Exibe o formulário de cadastro em lote. |
| `POST /admin/turmas/<id>/alunas/lote` | Cria até 100 contas em uma única transação. |
| `POST /admin/turmas/<id>/alunas/<aluna_id>/excluir` | Exclui uma conta sem movimentações. |

Cadastros e exclusões são permitidos apenas em turmas `AGENDADA` ou `ATIVA`. O lote é atômico: se qualquer inserção falhar, nenhuma conta daquele lote é mantida. Nomes iguais são aceitos, mas cada conta recebe um código distinto. Uma conta com Pix como origem ou destino não pode ser excluída.

## Fluxo planejado

1. O professor cria uma turma, define período, saldo inicial e senha da atividade.
2. O professor cadastra nomes autorizados para a turma, individualmente ou em lote por texto.
3. A aplicação gera contas temporárias e códigos aleatórios para as participantes.
4. Durante o período ativo, cada participante entra com código de conta e senha da turma.
5. Pix simulados ocorrem apenas entre contas da mesma turma.
6. Após a atividade, a turma pode expirar ou ser encerrada pelo professor.

## Decisões de segurança

- `CODIGO_ADMIN` continua exclusivamente no ambiente; não é copiado para o SQLite.
- A senha da turma é armazenada com PBKDF2-HMAC-SHA256 e sal aleatório, não em texto puro.
- Valores monetários usam `INTEGER` em centavos, sem `float`.
- O Pix usa uma transação SQLite com `BEGIN IMMEDIATE`: débito, crédito e registro são confirmados juntos ou revertidos juntos.
- A operação valida turma ativa, contas existentes, mesma turma, origem diferente do destino e saldo suficiente.
- Cookies e autenticação existentes da V1 continuam sendo usados pelas novas rotas administrativas.
- A inicialização apenas cria o schema do novo banco quando necessário; nunca importa ou sobrescreve dados V1 automaticamente.
- A exclusão valida a turma, a relação da aluna com ela e a ausência de transações antes de remover a conta.
